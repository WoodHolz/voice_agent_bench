# 测试集 v0.1

## 测试目标

在候选 SOP 已由上游正确提供的前提下，测试小 LLM 能否根据当前对话状态、最近历史和用户回复：

1. 选择正确的 SOP/意图编号；
2. 输出一条不超过 50 个汉字的语音 LLM 回复指导。

本版本不评测候选召回器和完整多轮控制器。候选项由数据集人工构造，正确答案保证在候选集中。

## 测例结构

- `input`：模型可见内容，包括状态、历史、用户回复和候选 SOP。
- `expected`：模型不可见的金标，包括可接受编号、状态变化、下一动作和回复指导要求。
- `metadata`：场景类型、难度、风险和审核状态。

模型标准输出：

```json
{"sop_id":"7-18","detail":"用户正在开车，立即停止沟通并约定方便时再联系。"}
```

## 判定规则

单条测例通过需要同时满足：

1. 输出为合法 JSON；
2. `sop_id` 位于本轮候选集中；
3. `sop_id` 位于 `acceptable_sop_ids`；
4. `detail` 覆盖 `must_include` 的业务含义；
5. `detail` 不包含 `must_not_include` 中的行为；
6. 不触发高风险错误；
7. 满足长度和延迟要求。

`detail` 不按参考答案逐字匹配。首轮由人工按语义复核，后续再开发自动评分器。

## 数据质量状态

v0.1 从产品文档表 7 自动抽取意图定义与示例，并生成候选干扰项。所有样本均为 `draft`：

- 必须检查意图边界是否符合 PM 定义；
- 必须检查回复指导是否符合话术与合规要求；
- 必须检查跨阶段样本的状态更新、跳过动作和下一动作；
- 经人工双人复核后才能改为 `approved` 并进入固定数据划分。

## 划分原则

同一 `group_id` 的原始场景及改写必须进入同一集合。推荐在审核完成后按组划分：

- dev：60%
- validation：20%
- test：20%

在划分前不得根据全量数据反复修改 Prompt；盲测集只在模型和 Prompt 定版后运行。
