# 节点约束 IntentRouter 实验结论

本轮结果部分支持“工作流状态约束语义搜索”：节点过滤显著改善局部集合外输入的拒识，但正例准确率只提高 **2.3 个百分点**，极性判断和误拒绝仍不足以支持业务动作。继续将 semantic-router 作为低延迟候选识别基线有价值，目前不能据此认定生产可用。

## 实验口径与产品映射

沿用四份产品文档和原有共享意图数据，导出 [节点映射](intent_data/workflow_intent_map.yaml)，逐边保留产品文件、行号、原文、意图 ID 与分支元数据。17 个局部回应/分类节点各含 2–7 个文本意图；分类器仍只输出 `7-xx`。未定义执行策略、补发动作或状态跳转。

产品 M5 允许主流程横切 a1–a6 旁路。因此，局部候选集合不等于整通电话所有合法意图。本轮 C 衡量局部回应识别，跨局部节点负例中属于合法旁路的输入另行标注；不能把它们称为产品非法输入。另做 S 旁路合并审计，主流程候选达到 33–38 个。该合并包含旁路入口及处理后回应，是文档候选上界，不是精确生产 Policy。

评测有 534 个节点样本、238 种用户文本。主结果排除 65 个产品原话/索引重叠样本，剩余 172 个单标签正例、289 个拒识负例和 8 个多标签歧义样本。三次重复用于延迟采样，不增加独立样本量。OOD 和部分短句跨节点复用，100% OOD 拒识不能外推到开放世界。

保持原模型、129 条索引例句、top-k=5、mean 聚合、阈值 0.65；没有训练、阈值调优或关键词补丁。A/B/C 使用相同样本交错执行。B 保留原实验的上下文索引方式，查询上下文由当前节点固定给出，不使用目标标签选择提示。分类入口的人工辅助提示在数据中明确标记。

## 对照结果

Accuracy 是单标签正例准确率；Overall 同时计正确拒识，排除多标签歧义。

| 配置 | Accuracy | Overall | OOD 拒识 | 局部节点外拒识 | 无效意图率 | p50 / p95 / p99 ms |
|---|---:|---:|---:|---:|---:|---|
| A 全局，仅用户文本 | 51.7% | 63.1% | 100.0% | 61.8% | 27.5% | 25.4 / 38.1 / 51.8 |
| B 全局，拼接对话 | 62.2% | 32.1% | 17.6% | 0.0% | 23.0% | 30.7 / 45.1 / 66.8 |
| C 节点过滤，仅用户文本 | 54.1% | 80.3% | 100.0% | 98.7% | 0.0% | 25.2 / 38.1 / 52.7 |

A→C：正例准确率 +2.3 pp，Overall +17.1 pp，局部节点外拒识 +36.8 pp；全局 OOD 拒识没有变化。节点过滤对拒识的帮助远大于对正例语义识别的帮助。

B 的正例准确率最高，但上下文导致大量不相关输入被接受。C 更适合继续验证结构化状态约束的架构方向；这不意味着 C 在全部指标上优于拼接对话。

C 的拒识 precision/recall 为 80.5%/95.8%，正例误拒率从 A 的 15.7% 升到 **39.0%**。负例被强行命中节点内标签的比例从 2.1% 升到 4.2%。例如在 `a1-5` 输入“我”，A 输出局部集合外的 `7-27`，C 输出集合内的 `7-15`，两者都不正确。结构性无效意图率为零不能代替准确率。

旁路审计在相同扩展真值和相同主流程节点上比较：A/B/S 正例准确率分别为 45.2%/54.8%/51.3%，Overall 为 57.5%/33.8%/65.8%，OOD 拒识为 100%/21.2%/100%。保留产品旁路后仍观察到过滤收益，但不能把 2–7 候选的主实验当作完整电话路由结果。

## 哪些节点和意图仍然困难

C 的 `a4` 操作问题节点准确率仅 10%，`a3-6-a` 时间安排回应为 25%，`b14-2` 页面状态为 37.5%，`b12-4` 查找通知和 `5-2-b-2` 完成状态均为 40%。较好的局部节点包括 `5-4-c`（85.7%）及邮箱确认 `b16-2-e-2`（100%，样本很少）。

专项中 C 没有出现指定的四个定向错误 `7-38→7-36`、`7-41→7-40`、`7-16→7-15`、`7-46→7-47`，但不能说极性问题已经解决：全部主结果中，`7-41` 的 10 个正例和 `7-16` 的 3 个正例都被拒识；`7-46` 准确率仅 25%。C 的专项极性准确率为 61.9%。[完整结果](reports/node_scoped/RESULTS.md) 同时列出定向错误、正确与拒识数量，以及逐节点、逐意图和混淆表。

实现仍采用原生 mean 聚合。过滤会改变进入 top-k 的例句组成，因而可能改变某个 route 的均值及阈值通过情况；这是一项机制解释，不是已经隔离验证的误拒原因。下一轮需要独立校准集验证阈值与聚合选择，不能直接用本测试集优化后报告泛化收益。

## 候选数量与延迟

| 局部候选数 | C 正例准确率 | C p50 / p95 ms |
|---|---:|---|
| 2 | 62.5% | 24.2 / 38.4 |
| 3 | 48.1% | 25.5 / 36.9 |
| 4 | 10.0% | 24.4 / 36.0 |
| 5 | 53.8% | 26.3 / 38.6 |
| 6 | 69.0% | 25.0 / 39.5 |
| 7 | 50.0% | 25.3 / 37.2 |

没有观察到随候选数减少而单调提高的准确率或明显延迟收益。不同组对应不同节点和难度，这不是受控改变候选数量的因果实验。此规模下 A/C 延迟几乎相同；索引很小，文本 embedding 的成本仍存在。

延迟来自本机 CPU、4 推理线程、串行无缓存的非空热请求，不含初始化、网络、ASR、TTS 或队列。背景负载未固定，尾延迟不是 SLA。

## 增量 ASR

复用原四条序列并增加五条极性序列，共 9 条、36 个 hypothesis，每种配置重复三次。按首轮：A→C 相邻预测变化从 15 次降至 6 次，低信息片段提前接受从 15 次降至 6 次，但最终正确从 **5/9 降至 3/9**。

`a4` 的修改信息和刷脸序列在 C 中持续拒识，预测不变并非稳定识别正确。完成状态序列也出现退化。因此本轮没有证明节点约束改善了“稳定且正确”的增量识别。早期 hypothesis 可能随 ASR 修订改变含义，与最终标签不一致不能自动算作当时语义错误。逐片段预测、score、延迟、变化和拒识见 [stream.json](reports/node_scoped/stream.json)。未实现投票、去抖、提交或动作执行。

## 实现与下一步判断

使用上游公开的 `SemanticRouter(text, route_filter=allowed_intents)`；已检查本地固定提交的 `LocalIndex.query`，在相似度计算和 top-k 之前过滤向量。测试用真实上游索引验证该顺序，避免全局分类后丢弃无效结果。节点只用于选择候选，C 的 embedding 输入始终为当前用户文本。未知节点显式报错，不回退全局。

score 是检索 top-k 中获选 route 例句的平均余弦相似度，不是概率。被阈值拒识时，上游可能返回空 score；它不表示零概率。过滤和上下文会改变分数分布，本轮没有跨配置置信度校准。

建议保留 semantic-router 作为下一轮快速候选路由基线，优先验证误拒、极性表达和合法旁路边界；当前证据不支持直接接入业务动作。原 RealtimeIntent 实验和旧报告保持不变。全套测试 **17 passed**，覆盖候选预过滤、节点校验、数据来源及拒识指标。复现命令见 [运行说明](node_scoped/README.md)，原始完整指标见 [benchmark.json](reports/node_scoped/benchmark.json)。
